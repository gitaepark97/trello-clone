## Purpose

보드(Board)는 사용자가 리스트와 카드를 담아 작업을 조직하는 최상위 작업 공간이며, 생성/조회/수정/삭제의 기본 관리 기능을 제공한다.

## ADDED Requirements

### Requirement: 보드 생성
시스템은 제목(title)을 포함한 요청으로 새 보드를 생성해야 한다(SHALL). 제목은 필수이며 설명(description)은 선택 항목이다.

#### Scenario: 제목을 포함해 보드를 정상적으로 생성
- **WHEN** 사용자가 제목을 포함한 보드 생성 요청을 보내면
- **THEN** 시스템은 새 보드를 생성하고 고유 식별자를 포함한 보드 정보를 반환한다

#### Scenario: 제목 없이 보드 생성 시도
- **WHEN** 사용자가 제목 없이(또는 빈 문자열로) 보드 생성 요청을 보내면
- **THEN** 시스템은 요청을 거부하고 유효성 오류를 반환한다

### Requirement: 보드 목록 조회
시스템은 삭제되지 않은 보드의 목록을 조회할 수 있어야 한다(SHALL).

#### Scenario: 보드 목록 조회
- **WHEN** 사용자가 보드 목록 조회를 요청하면
- **THEN** 시스템은 삭제되지 않은 모든 보드를 반환한다

### Requirement: 보드 단건 조회
시스템은 식별자로 특정 보드를 조회할 수 있어야 한다(SHALL).

#### Scenario: 존재하는 보드 조회
- **WHEN** 사용자가 존재하는 보드의 식별자로 조회를 요청하면
- **THEN** 시스템은 해당 보드의 상세 정보를 반환한다

#### Scenario: 존재하지 않는 보드 조회
- **WHEN** 사용자가 존재하지 않는(또는 이미 삭제된) 보드 식별자로 조회를 요청하면
- **THEN** 시스템은 찾을 수 없음 오류를 반환한다

### Requirement: 보드 수정
시스템은 보드의 제목과 설명을 수정할 수 있어야 한다(SHALL).

#### Scenario: 보드 제목/설명 정상 수정
- **WHEN** 사용자가 존재하는 보드에 대해 제목 또는 설명 변경을 요청하면
- **THEN** 시스템은 해당 보드 정보를 갱신하고 변경된 결과를 반환한다

#### Scenario: 존재하지 않는 보드 수정 시도
- **WHEN** 사용자가 존재하지 않는 보드 식별자로 수정을 요청하면
- **THEN** 시스템은 찾을 수 없음 오류를 반환한다

### Requirement: 보드 삭제
시스템은 보드를 삭제할 수 있어야 하며(SHALL), 보드가 삭제되면 해당 보드에 속한 모든 리스트와 카드도 함께 삭제되어야 한다(MUST).

#### Scenario: 보드 삭제 시 하위 리스트/카드 함께 삭제
- **WHEN** 사용자가 리스트와 카드를 포함한 보드의 삭제를 요청하면
- **THEN** 시스템은 해당 보드와 그에 속한 모든 리스트, 카드를 삭제한다

#### Scenario: 존재하지 않는 보드 삭제 시도
- **WHEN** 사용자가 존재하지 않는 보드 식별자로 삭제를 요청하면
- **THEN** 시스템은 찾을 수 없음 오류를 반환한다
