## Why

Trello 클론을 만들기 위해서는 가장 먼저 보드(Board), 리스트(List), 카드(Card)로 이어지는 핵심 도메인 모델과 기본 동작(생성/조회/수정/삭제, 순서 변경)이 정의되어야 한다. 인증/인가나 협업(멤버 초대, 실시간 동기화) 같은 기능은 이 핵심 도메인 위에 쌓이는 것이므로, 먼저 이 부분을 확정해야 이후 스펙들이 안정적인 기반 위에서 진행될 수 있다.

## What Changes

- 보드(Board) 생성/조회/수정/삭제(CRUD) 기능 정의
- 리스트(List) 생성/조회/수정/삭제(CRUD) 및 보드 내 순서 변경 기능 정의
- 카드(Card) 생성/조회/수정/삭제(CRUD), 리스트 내 순서 변경, 리스트 간 이동 기능 정의
- 보드 → 리스트 → 카드로 이어지는 계층 구조와 각 엔티티 간 참조 무결성 규칙 정의 (예: 보드 삭제 시 하위 리스트/카드 처리 방식)

이번 변경에는 사용자 인증/인가, 멤버 초대, 라벨, 댓글, 첨부파일 등은 포함하지 않는다 (범위 밖, 후속 변경에서 다룸).

## Capabilities

### New Capabilities
- `board`: 보드 생성/조회/수정/삭제(CRUD) 및 보드 목록 조회
- `list`: 보드에 속한 리스트의 CRUD와 보드 내 순서 변경(재정렬)
- `card`: 리스트에 속한 카드의 CRUD, 리스트 내 순서 변경, 다른 리스트로의 이동

### Modified Capabilities
(없음 - 그린필드 프로젝트로 기존 스펙이 존재하지 않음)

## Impact

- 신규 백엔드(Spring Boot) API: 보드/리스트/카드에 대한 REST 엔드포인트, PostgreSQL 스키마(테이블: `board`, `list`, `card`)
- 신규 프론트엔드(React): 보드 목록/상세 화면, 리스트·카드 표시 및 CRUD·순서 변경 UI
- 이후 변경(사용자 인증, 보드 멤버십 등)이 이 스펙의 엔티티(특히 `board`)를 확장할 것으로 예상됨 (예: `board.ownerId` 필드는 이번 단계에서는 인증 없이 단일 사용자 가정 또는 임시 식별자로 둘 수 있음 - design.md에서 구체화)
